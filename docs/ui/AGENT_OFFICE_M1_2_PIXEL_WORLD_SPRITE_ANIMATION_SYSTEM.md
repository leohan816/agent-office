# Agent Office M1.2 Pixel-World Sprite and Animation System

Status: `DESIGNED_PIXEL_WORLD_SPRITE_SYSTEM__PENDING_CLEAN_FABLE5_LEVEL3_DESIGN_PASS__NO_ASSET_OR_RUNTIME_IMPLEMENTATION_AUTHORIZED`

Design base: `48c8dbd9f2c5ecea68c28e85137d75db595ef5f9`

Candidate contracts:

```text
agent-office.pixel-atlas.v1
agent-office.pixel-character-presentation.v1
agent-office.pixel-world-frame.v1
```

This document defines the original code-native sprite and animation layer for
the living pixel-office candidate. It does not add a domain event, actor,
authority, assignment, notification, workflow state, transport route, or
completion rule. It consumes only the already-validated M1.2 spatial projection
and the existing bounded cue reducer.

No atlas, raster image, dependency, asset, script, test, package, or runtime
change is authorized by this design pass.

## 1. Truth boundary

The pixel system is a deterministic presentation function:

```text
validated SpatialOfficeProjectionV1
  + validated SpatialCueReducerState
  + explicit presentation tier
  + explicit camera state
  + explicit logical presentation time
  -> PixelWorldFrameV1
```

It may not query Git, a filesystem, tmux, process state, a gateway, an event
store, network state, terminal/model prose, wall-clock mission duration, or
unverified browser data. It never emits a domain event or writes a projection.

Every operational animation requires an already-eligible accepted cue from
[`../contracts/AGENT_OFFICE_M1_2_SPATIAL_EVENT_ANIMATION_CONTRACT.md`](../contracts/AGENT_OFFICE_M1_2_SPATIAL_EVENT_ANIMATION_CONTRACT.md).
An authenticated initial snapshot may select an exact static pose but must not
play the transition that led there. Neutral ambient motion carries no
operational meaning.

## 2. Original visual direction

The visual language is project-authored, cute, warm, readable, and blocky:

- orthographic/top-down 2D with light 2.5D wall and furniture faces;
- logical `16 x 16` floor tiles and integer-pixel silhouettes;
- warm wood, slate, glass, plants, fabric, monitors, paper, mugs, and lamps;
- exaggerated role silhouettes and props that remain legible at `2x` scale;
- one shared American-style open office rather than separate cards or rooms
  that disappear on selection; and
- no imitation of Minecraft, a protected game, franchise, artist, character,
  distinctive sprite set, or trade dress.

There is no sound, speech bubble content, generated dialogue, particle storm,
parallax, screen shake, flashing, physics, or unbounded loop. The office remains
an operations presentation, not a game that invents collaboration or progress.

## 3. Atlas source and ownership contract

### 3.1 Selected source class

The bounded prototype uses original project-authored **code-native atlas
sources**. Source modules contain explicit indexed-palette pixel matrices and
frame metadata. A deterministic local builder converts those matrices into an
RGBA atlas in memory or into reviewed local build artifacts. No external image,
font, model, CDN, URL, download, purchase, import, runtime generation service, or
protected reference is permitted.

The same source values must generate byte-equal RGBA output for the same
builder version. If a future implementation chooses committed PNG/JSON outputs,
their generated bytes, generator version, and hashes must be committed with the
source and inventory. If runtime generation is used, the source hash and the
generated RGBA hash must be asserted in tests before texture creation.

### 3.2 Atlas set

The renderer may load at most four texture sources:

| Atlas | Maximum size | Contents |
|---|---:|---|
| `office-world.v1` | `1024 x 1024` | Walls, flooring, doors, glass, desks, computers, meeting room, lounge, walkways, Advisor hubs, Reviewer booth, signs, boards, plants, Channy facilities, route props |
| `actor-base.v1` | `512 x 1024` | Neutral role silhouettes and exact animation frames |
| `actor-identity.v1` | `512 x 512` | Clothing accents, patterns, role/project glyphs, badges, documents, tools, coffee/rest props, operational overlays |
| `channy.v1` | `512 x 512` | One Bedlington Terrier and its allowed state frames |

Every texture uses nearest sampling, no mipmap dependency, no antialiasing, and
fixed intrinsic dimensions. No user or projection value becomes an asset URL or
frame name.

Every atlas entry is validated before Pixi texture creation:

```text

sourceSha256

generatedFileSha256 (optional)

```

Each frame contains:

```text

```

Frames may overlap neither each other nor atlas bounds. Pivots, feet, and
collision footprints are integers. An unknown atlas version, missing frame,
hash mismatch, duplicate frame, invalid geometry, external reference, or
license/ownership failure selects the DOM static/M1 fallback.

### 3.4 Asset inventory and replacement

The later prototype must add an inventory adjacent to the source. It records
every atlas and palette hash, builder command, generated-output hash, ownership,
license, visual use, dimensions, frame/animation coverage, and reviewed commit.
The existing M1 and AO12-B placeholder inventories remain immutable evidence.

No prototype asset is automatically production-approved. A replacement must
retain stable semantic animation IDs, pass the complete matrix, update hashes
and licensing atomically, and receive separate review. Replacing visual bytes
cannot change role identity, assignment, project identity, state, evidence, or
authority.

## 4. Character composition

One visual actor is composed from deterministic layers:

```text
shadow
  -> role-category base silhouette
  -> project clothing/pattern overlay
  -> role prop
  -> task prop, only for an eligible cue
  -> operational safety/state overlay
  -> focus/selection ring, DOM-equivalent
```

Layer precedence is:

```text
quarantine/recovery
  > critical alert
  > freshness/connection/assignment conflict
  > BLOCKED / WAITING_LEO / HOLD / NEEDS_PATCH
  > accepted operational cue
  > verified current static pose
  > project identity
  > decorative detail
```

Higher layers may suppress lower-layer motion. A project palette never colors a
critical border, focus indicator, freshness marker, review verdict, evidence
verification, or authority marker.

## 5. Actor sprite-sheet contract

### 5.1 Base geometry and directions

- Full actor frame: `32 x 48` logical pixels.
- Foot anchor: `(16, 44)` unless a manifest entry supplies another reviewed
  integer value.
- Directions: `NORTH`, `SOUTH`, `EAST`, and `WEST`.
- West may mirror a reviewed east frame only when `allowedMirrorX=true`; text,
  asymmetrical project glyphs, documents, and role props use dedicated overlays
  so mirroring cannot reverse meaning.
- A canonical `roleInstanceId` owns at most one visible full actor sprite across
  the world. Other assignments are DOM/pixel glyph references only.

### 5.2 Required actor animations

| Animation ID | Minimum frames | Frame duration | Loop/limit | Meaning and gate |
|---|---:|---:|---|---|
| `actor.idle.<direction>` | 4 | `250ms` | Neutral loop only in eligible ambient tier; otherwise frame 0 | Verified current identity, no availability or assignment claim |
| `actor.walk.<direction>` | 6 | `100ms` | Only for one resolved bounded route | Accepted route or verified-idle relocation; path position is presentation only |
| `actor.sit.<direction>` | 2 | `400ms` | Static or bounded neutral loop | Verified idle or current seated static pose |
| `actor.type.<direction>` | 4 | `120ms` | Maximum `900ms` per eligible cue | Accepted `WORKING`; keyboard movement is not progress |
| `actor.review.<direction>` | 4 | `160ms` | Maximum `1000ms` | Accepted independent `REVIEW`; Reviewer remains separate |
| `actor.carry-document.<direction>` | 6 | `100ms` | One route, maximum cue duration | Accepted delivery/review-handoff/decision route; one document prop |
| `actor.return-result.<direction>` | 6 | `100ms` | One route, maximum cue duration | Accepted result/verdict/patch return; not completion or approval |
| `actor.coffee.<direction>` | 4 | `300ms` | One bounded ambient burst | Verified idle; no communication or availability meaning |
| `actor.rest.<direction>` | 2 | `500ms` | Static or bounded ambient | Verified idle only |
| `actor.lounge.<direction>` | 4 | `300ms` | One bounded ambient burst | Verified idle lounge presentation only |

The atlas must also contain static frames for `READING`, `TESTING`,
`WRITING_RESULT`, `WAITING_DEPENDENCY`, `WAITING_LEO`, `BLOCKED`, `COMPLETED`,
`FAILED`, `CANCELLED`, and `RECOVERY`. Bounded prop/overlay frames may animate
only under the existing cue durations. Initial load, reload, resume, selection,
orientation change, and static mode use an exact non-moving frame.

### 5.3 Role silhouettes and props

| Role category | Silhouette/prop | Required text/glyph equivalent |
|---|---|---|
| `LEO_DECISION` | Decision door/document and neutral destination | `Leo/GPT decision destination`; never a command target |
| `ADVISOR_ROUTING` | Routing sash, inbox tray, carried document | Exact Advisor role instance and responsibility reference |
| `CONTROL_RECOVERY` | Console/tool belt | Exact Control role and recovery state |
| `INDEPENDENT_REVIEW` | Lens/checklist, separate booth | `Fable5 Reviewer`, independent review |
| `WORKER_BUILD` | Work apron/keyboard/tool | Exact Worker role and project assignment |
| `GENERIC_REGISTERED` | Neutral silhouette | Exact registered role text; no inferred person/model identity |

No sprite is a real-person likeness, model/provider logo, or proof of the actor's
presence. Model/session identity remains redacted registered text in the DOM
detail layer.

## 6. Project and Team identity in the pixel world

Spatial grouping remains Advisor Team first. Project identity repeats through
at least four independent channels:

1. full project/Team text in the DOM HUD and detail surface;
2. a fixed project glyph on sign, board, desk, and clothing;
3. a fixed project pattern on clothing and Pod floor/sign trim;
4. an approved palette accent on clothing, sign, desk prop, and route document;
5. a role-specific prop or silhouette independent of project; and
6. optional short label on a pixel sign where it remains legible.

The approved palette remains Cosmile coral/pink, SIASIU mint/emerald,
Foundation navy/blue, VibeNews purple, Agent Office orange/amber, and Control
slate/charcoal with a blue accent. Color is never the only identifier. Unknown
future projects use the existing deterministic catalog tuple; selection order,
camera, browser, locale, and activity cannot change it.

In-world mission boards show only concise, stable facts: mission short label,
current WorkUnit short ID, actor glyph, operational-state glyph, exact
`completed/denominator`, gate progress, and one blocker/Leo-alert marker. Full
names, Korean/English labels, evidence, hashes, and timestamps stay in DOM to
avoid font-dependent canvas truth and dense overlays.

## 7. Channy Bedlington Terrier contract

Channy remains exactly one global presentation character with:

```text
authorityRole: none
roleInstanceId: none
assignmentRefs: []
commandTargets: []
directEventSubscriptions: []
evidenceWrites: []
```

Base frame: `48 x 40` logical pixels; foot anchor `(24, 36)`.

| Animation ID | Minimum frames | Frame duration | Gate and meaning |
|---|---:|---:|---|
| `channy.roam.<direction>` | 6 | `120ms` | Neutral browser-local path or brief follow of an already accepted route |
| `channy.sit.<direction>` | 3 | `300ms` | Neutral/static presentation |
| `channy.eat` | 4 | `180ms` | Neutral at exact food anchor; no source/activity claim |
| `channy.drink` | 4 | `180ms` | Neutral at exact water anchor |
| `channy.sleep` | 4 | `500ms` | Neutral at exact bed anchor; no system-idle claim |
| `channy.play` | 6 | `140ms` | Neutral in bounded lounge/path zone |
| `channy.react-waiting-leo` | 3 | `250ms` | Structured status reflector; static in reduced motion |
| `channy.react-blocked` | 3 | `250ms` | Structured status reflector; task/ambient movement otherwise suppressed |
| `channy.react-complete` | 4 | `200ms` | Structured mission-complete reflector; never approval |
| `channy.react-stale-offline` | 1 | static | Exact static suppression state |

Precedence remains:

```text
STALE/OFFLINE/CONFLICT static
  > BLOCKED
  > WAITING_LEO
  > mission complete
  > already accepted route follow
  > neutral ambient schedule
```

Channy cannot inspect sessions, infer work, carry a command, deliver a real
document, notify a role, repair a system, approve a decision, replace an alert,
or imply collaboration. Bed, food, and water are decorative facility anchors.
Primary DOM status always carries meaning independently of Channy.

## 8. Accepted cue to pixel presentation mapping

The existing cue envelope is authoritative. This layer maps it without changing
eligibility, source IDs, precedence, or duration.

| Existing cue | Actor/prop presentation | End/static result |
|---|---|---|
| `LEO_GPT_TO_ADVISOR_HANDOFF` | One Advisor `carry-document` path from decision destination to Advisor Hub | Exact route row and evidence pointer; no approval |
| `DELIVERY` | One Advisor walk/carry path to assigned Worker; handoff frames | `DISPATCHING`/route text; no automatic start |
| `READING` | Static reading pose plus bounded page prop | Exact reading state and source IDs |
| `WORKING` | Bounded `type` microcycle at assigned desk | Exact `WORKING` label; no progress change |
| `TESTING` | Static test pose plus bounded checklist/tool frames | `TESTING`; never pass |
| `WRITING_RESULT` | Seated/standing result pose plus bounded paper frames | `WRITING_RESULT`; not reported result |
| `REVIEW_HANDOFF` | One document route to separate Reviewer booth | Reviewer assignment and route row |
| `REVIEW` | Reviewer-only `review` microcycle | Exact review state; no verdict |
| `REVIEW_VERDICT_RETURN` | Reviewer `return-result` route to Advisor Hub | Verdict evidence text; no approval |
| `BLOCKED` | Immediate barrier/alert overlay, no walking | Persistent reason/owner/route in DOM |
| `WAITING_LEO` | One decision-document path, then static attention pose | Persistent decision request; no decision |
| `RESULT_RETURN` | Exact actor `return-result` route with one result prop | Result pointer/receipt distinction; no completion |
| `PATCH_RETURN` | One patch document route from Reviewer to exact Worker | `NEEDS_PATCH`; not a new dispatch |
| `COMPLETION_ACKNOWLEDGEMENT` | One board acknowledgement prop | Completed plus exact acknowledgement evidence; no next mission |
| `RECOVERY` | Control-only bounded tool frames | Exact step/total/read-only status |
| `IDLE_RELOCATE` | One verified actor walks to a valid ambient anchor | `VERIFIED_IDLE`; no availability meaning |

`cue.durationMs` caps the full visual sequence. A route phase may allocate that
duration deterministically to depart, travel, interaction, and return/current
pose. Animation callbacks may remove presentation state only; they cannot emit
events or change the projection.

## 9. Precedence, concurrency, and actor uniqueness

The existing M1.2 precedence remains exact. Pixel presentation adds no state.

- maximum three pending transient cues in the selected Team;
- maximum one route at a time;
- maximum one operational cue per canonical actor;
- maximum one full visual character per `roleInstanceId` across the floor;
- maximum one neutral ambient actor plus the one global Channy;
- non-selected Pods show verified static poses and concise board changes, not
  full task choreography;
- same-actor or same-WorkUnit bursts coalesce to the existing precedence winner;
- excess eligible cues become DOM activity-log rows and are marked seen; and
- critical, stale, offline, unknown, conflict, and error facts render
  immediately and suppress affected motion.

If a route would require a second copy of an actor, it is static-only. If one
actor has incompatible simultaneous active assignments, render one actor in
`ASSIGNMENT_CONFLICT`, list the exact assignments in DOM, and run no task or
ambient animation.

## 10. Deduplication, stale/conflict suppression, and replay

The pixel layer receives cue IDs only after the existing reducer. It also keeps
the applied `frameKey` so a React rerender cannot restart an animation.

- Initial/full/reload/reset/resume snapshots render current static poses, mark
  source/cue IDs seen, and enqueue nothing.
- `POD_SELECTION` and camera movement never create or restart a cue.
- A non-selected Pod does not save movement for later entertainment.
- Duplicate cue IDs update neither route nor sprite phase.
- Duplicate projection revision with changed content selects conflict/static.
- Stale/offline/unknown/conflict/error or a critical alert cancels the affected
  visual and discards it; fresh evidence does not replay it.
- Hidden tab, orientation change, context loss, renderer fallback, logout,
  expiry, revocation, and unmount discard transient presentation.
- Neutral ambient time is browser-local and is never stored as mission history.

## 11. Deterministic clock and frame selection

`PixelWorldFrameV1` is a pure function of the explicit logical time. It uses no
`Date.now()`, random number, CSS animation clock, `setInterval`, locale-sensitive
sort, font measurement, or renderer frame count.

### 11.1 Operational sequences

For a cue with duration `D`, normalized progress is
`clamp((logicalTimeMs - cueStartMs) / D, 0, 1)`. Frame selection uses integer
division by the manifest frame duration. Routes sample a committed path using a
fixed easing table or an explicitly versioned easing function. Tests freeze the
exact logical time and current camera.

### 11.2 Neutral ambient schedule

Neutral actor/Channy schedules use a deterministic presentation seed derived
from the fixture/world-layout version for tests and a non-authoritative browser
session seed for ordinary presentation. A seed never contains an event, actor
authority, credential, path, session locator, or user content. The same seed,
layout, and logical time produce the same frame.

Neutral actor movement remains a maximum `600ms` burst followed by at least
`8s` static. Channy may use longer neutral scene segments for roam/eat/drink/
sleep/play, but a new operational/safety input interrupts immediately. Neither
schedule appears in evidence or progress.

### 11.3 Scripted prototype clock

The prototype uses a committed synthetic scenario timeline and a test-only
clock. The 20-to-30-second recording advances that clock continuously; still
baselines set it to exact millisecond checkpoints. A production module must not
import the scenario, clock controls, fixture IDs, or recording markers.

## 12. Camera, z-order, and occlusion

Z-order is derived from layer then integer foot `y`, then stable entity ID:

```text
floor
  < floor props and rugs
  < walls/furniture backs
  < characters and movable props by foot y
  < furniture fronts/glass highlights
  < route/status visual overlays
```

Camera selection never changes z-order or identity. A focused actor may receive
a selection ring but is not brought above walls or safety overlays. Occluded
actors retain exact DOM semantics and may receive a subtle non-semantic outline;
the camera does not infer a new location to expose them.

## 13. HUD and detail correspondence

The concise DOM HUD and pixel signs share the same frame model fields:

```text
frameKey
selectedPodId
selectedTeamName
selectedProjectId and identity tuple
missionShortLabel
currentWorkUnitShortId
currentActorRoleInstanceId
operationalState
workUnitProgress
requiredGateProgress
blockerSummary
leoAlertSummary
freshness and connection
```

The detailed DOM drawer receives the full validated mission-board/evidence model
directly, not text extracted from a pixel sign. A parity assertion verifies that
every entity rendered in Pixi appears in the semantic mirror and that the mirror
has no conflicting state for the same `frameKey`. A mismatch selects static
presentation and logs a redacted `RENDERER_SEMANTIC_DIVERGENCE` diagnostic.

## 14. Reduced motion, static equivalence, and high contrast

- `prefers-reduced-motion`, motion off, or static tier stops the private ticker
  and calls `gotoAndStop` at the exact current static frame before unmounting or
  hiding the visual world.
- Route meaning becomes immediate origin-to-destination text with document kind
  and source references.
- Actor state becomes exact text/icon/shape plus a non-moving sprite or existing
  DOM placeholder.
- Channy becomes one neutral or structured-reflector pose with independent
  primary status text.
- Forced colors may hide the canvas; system colors, text, borders, glyphs,
  focus, and severity remain in the DOM mirror.
- At 200-percent text and 320px, no essential canvas label is required; the DOM
  HUD/drawer wraps normally and mobile Pod navigation remains usable.

No CSS animation is a required fallback, and no information waits for a Pixi
completion callback.

## 15. Test contract

### 15.1 Pure and component tests

- validate every atlas field, dimension, frame, pivot, collision footprint,
  source/generated hash, ownership, license, and prohibited external reference;
- require every actor and Channy animation ID and minimum frame count;
- prove exact project palette/glyph/pattern/clothing/sign/prop identity and
  color-independent semantics;
- map every existing cue to exact allowed frames and reject unaccepted,
  prose-shaped, stale, conflicting, duplicate, replay, and cross-project inputs;
- prove precedence, three-cue/one-route/one-actor caps and no actor/Advisor/Channy
  cloning;
- prove deterministic layout, A* tie-breaks, z-order, frame selection, scripted
  time, camera clamp, full-office return, mobile focus, and focus restoration;
- prove Pixi/DOM `frameKey` and entity/state correspondence; and
- keep renderer modules free of observation, filesystem, process, gateway,
  tmux, event-write, HTTP mutation, remote asset, and arbitrary command imports.

### 15.2 Browser and visual tests

- run the thirteen-row matrix in the renderer design under configured Chromium;
- exercise WebGL and the Canvas core subset separately, or classify Canvas as
  unsupported and select DOM static;
- simulate context loss/restore, initialization failure, lazy-chunk failure,
  image/hash failure, resize, orientation, hidden/resume, logout, expiry,
  revocation, and StrictMode remount;
- prove keyboard, screen reader semantics, live-region bounds, `44 x 44` targets,
  320px, mobile, 200-percent text, reduced motion, forced colors, axe WCAG A/AA,
  and no overlap/clipping;
- measure bundle, startup, frames, long tasks, object/texture counts, heap,
  canvases, tickers, observers, listeners, and teardown; and
- prove every historical M1, AO12-B, AO12-C, and AO12-D baseline byte remains
  unchanged unless a later exact handoff explicitly authorizes a new separate
  living-office baseline directory.

### 15.3 Prototype media truth

The WebM must come from the actually running loopback prototype and show
continuous movement and transitions. The MP4 and GIF must be conversions of
that WebM, not reconstructed frames. The GIF must include actor walking, Channy
roaming, and the Advisor document handoff. Exact paths, bytes, SHA-256 values,
scenario, source commit, capture command, and conversion commands are required.

## 16. Failure and rollback behavior

Any of the following selects `DOM_STATIC` without delayed replay:

- unsupported or failed renderer;
- unknown atlas or frame contract;
- ownership/license/hash/geometry failure;
- unavailable or lost context;
- frame-model/semantic-mirror divergence;
- camera/world bounds invalidity;
- object/texture/bundle/frame/memory budget miss;
- accessibility equivalence failure; or
- cleanup evidence that retains a canvas, ticker, listener, observer, cue, or
  texture.

An invalid authenticated spatial projection selects the unchanged
`M1_FIXED_STATIONS` path as it does today. Rollback is presentation-only and
cannot run Git, rewrite evidence, restart a role, change auth/authority/transport,
or begin another mission.
